Zana Connect adapts the account-owned server/device enrollment, expiring pairing code, server discovery and authenticated tunnel model from BB Connect (MIT, Copyright 2026 Michael Yong), source snapshot fdd3de3b19b97e6cd1ef7300cbb54711431249d3. BB-LICENSE contains the original license. Runtime code is adapted to Node/Heroku and the existing Zana account system; no BB production domains or credentials are used.

Personal browser addresses follow that snapshot's `apps/web/src/routes/dashboard.tsx` ClaimView, `packages/connect-db/src/constants.ts` label validation, and `apps/connect/src/worker.ts` owner-authorized browser routing. Zana keeps stable tunnel URLs and adds permanent aliases. Its browser authentication uses a one-use handoff and host-only cookies in place of BB's parent-domain account cookie.

Execution-machine enrollment adapts `apps/web/src/server/api.ts` createMachineCode/redeemMachineCode and `apps/connect/src/worker.ts` machine authorization from the same snapshot. Zana binds each machine to a particular instance/host, keeps phone grants separate, encrypts the short-lived inner enrollment token, and supports lost-response recovery using a client-held attempt secret. The original MIT notice is retained in BB-LICENSE.
